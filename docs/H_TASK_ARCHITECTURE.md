# H 题动态架构与固件任务

## 1. 架构结论

本工程设计 3 台状态机。题目 2~6 是模式配置，不是状态。

| 状态机 | 类型 | 状态数 | 职责 |
| --- | --- | ---: | --- |
| `AppCar` | 母机 | 4 | 启停、完成、故障和消息分发 |
| `Route` | 子机 | 5 | 离开 A、循线、终点动作和完成 |
| `Ball` | 子机 | 5 | 等待视觉、正负位置运动和稳定控制 |

父机处于 `RUNNING` 时，每个 2 ms 控制消息依次运行 `Route` 和 `Ball`，因此小车循线和钢球稳定可以并行执行。

## 2. 状态定义

### AppCar 母机（4 状态）

| 状态 | 进入条件 | 行为 | 离开条件 |
| --- | --- | --- | --- |
| `STOPPED` | 上电、人工停止 | 电机停止、舵机回中 | `MSG_KEY_START` -> `RUNNING` |
| `RUNNING` | 启动 | 2 ms 同时运行 Route 和 Ball | 完成、停止或故障 |
| `FINISHED` | 任务达标 | 停车、冻结总时间；Ball 可继续保持 | 再次启动或停止 |
| `FAULT` | 安全故障 | 电机停止、舵机回中 | 人工确认后回 `STOPPED` |

### Route 子机（5 状态）

| 状态 | 作用 |
| --- | --- |
| `DISABLED` | 静态滚球题不运行小车 |
| `LEAVE_START` | 起点全黑时先直行离开 A，避免把起点当终点 |
| `TRACKING` | 运行循迹控制和后续轮速 PI |
| `FINISH_ACTION` | 执行题目对应的过线或定点停车动作 |
| `COMPLETE` | 通知母机进入完成状态 |

### Ball 子机（5 状态）

| 状态 | 作用 |
| --- | --- |
| `DISABLED` | 纯循迹题关闭滚球控制 |
| `WAIT_VISION` | 等待 K230 有效位置，禁止盲目控制舵机 |
| `MOVE_POSITIVE` | 静态题控制钢球到 `+50 mm` |
| `MOVE_NEGATIVE` | 静态题从 `+50 mm` 折返至 `-50 mm` |
| `HOLD_TARGET` | 在 `0 mm`、`-50 mm` 或指定目标附近持续稳定 |

## 3. 五种模式映射

| 串口模式 | 对应要求 | Route 初态 | Ball 初态 | 完成判据 |
| --- | --- | --- | --- | --- |
| `2` | 第 2 项：循线一圈停 A | `LEAVE_START` | `DISABLED` | 编码器达到一圈门槛后检出 A 线，补偿循迹后停车 |
| `3` | 第 3 项：静态 `+5 -> -5 cm` | `DISABLED` | `WAIT_VISION` | `-50 mm` 误差不超过 `10 mm` 并稳定指定时间 |
| `4` | 第 4 项：A 到 B、球稳 O | `DISABLED`，视觉有效后进入 `LEAVE_START` | `WAIT_VISION` | 编码器里程到 AB，同时球目标为 `0 mm` |
| `5` | 第 5 项：一圈、球稳 O | `DISABLED`，视觉有效后进入 `LEAVE_START` | `WAIT_VISION` | 再次通过 A，同时球目标为 `0 mm` |
| `6` | 第 6 项：一圈、球稳指定点 | `DISABLED`，视觉有效后进入 `LEAVE_START` | `WAIT_VISION` | 再次通过 A，同时球保持指定目标 |

## 5. 固件队友任务单

架构接口、状态枚举和 `msg_map` 不改。队友按以下顺序填充代码。

### P0：钢球闭环

1. 标定摄像头：建立像素到摆杆毫米位置的转换，覆盖至少 `-60~+60 mm`。
2. 将 K230/G3507 之间的数据统一为物理位置；协议变更必须同时修改两端并记录单位。
3. 新建连续控制器 `ball_control.h/.c`，输入目标位置、实际位置和有效标志，输出安全范围内的舵机脉宽。
4. 填充 `_BallMovePositive`、`_BallMoveNegative`、`_BallHoldTarget`。
5. 状态切换必须使用“误差不超过 10 mm + 连续稳定时间”，不能用单帧命中。
6. 视觉失效时不得保持旧控制量；超时应停止控制并上报故障。
7. H6 的指定位置通过 `appCarCon.setBallTargetMm()` 写入，不直接修改实体成员。

交付测试：静止小车完成 `0 -> +50 -> -50 mm`，总时间不超过 5 s，最大位置误差不超过 10 mm。

### P0：小车闭环和里程

1. 架空车轮验证两个编码器方向，并确认每个车轮一圈约为 `1456` 个计数。
2. 实测 H2 一圈的 OLED `ENC`；当前预计值约 `43837`，80% 放行门槛约 `35069`。
3. 实测 `_RouteFinishAction` 的停车位置，调整顶部 `APP_CAR_FINISH_FOLLOW_MS`。
4. 新建左右轮速度 PI，使循迹输出成为目标轮速，不再直接等同 PWM 百分比。
5. H4 使用累计里程判断 AB；H2、H5、H6 使用里程门槛加 A 启停线判断一圈。

交付测试：纯循迹一圈不脱线，20 s 内停车，基准位置偏差不超过 20 mm。

### P0：计时显示

1. 和硬件负责人确定无引脚冲突的显示接口；题目要求显示屏不大于 2 英寸。
2. 增加显示 BSP，只显示模式、运行时间、完成/故障等必要信息。
3. 启动按键时清零并开始计时，完成状态冻结最终时间。

交付测试：断开调试串口后，车载屏仍能独立显示本次总时间。

### P1：联调与安全

1. 视觉超时、状态函数空指针、控制超时进入 `FAULT`。
2. 所有舵机测试先限制脉宽并架空机构；所有电机测试先架空车轮。
3. 串口遥测保留父状态、Route、Ball、球位置、灰度、编码器、控制量和队列溢出数。
4. 每完成一个控制器，先做模块测试，再接入状态机，不直接在 BSP 中写题目流程。

## 6. 不允许混放的职责

```text
SysTick / IRQ : 采样、计时、投递消息
msg_map       : 缓存和传递事件
BSP           : 操作具体硬件
control       : 连续算法（循迹、PI、PD）
app_car       : 状态、转移条件和题目流程
main          : 初始化、取消息和统一调度
```

固件队友不得在中断中运行 PID、打印串口或直接切换题目状态，也不得绕过 `appCarCon` 从 `main` 操作实体内部数据。
